# 语义经验：初始化失败后未中止操作

## 触发
构造函数 / init 函数里出现失败检查（返回 false、抛异常、错误码），
但其后的代码仍继续使用这个对象。

## 判断
把「失败检查」和「后续使用」看成同一条控制流来审查：只要存在
「失败后仍继续使用」的路径就报违规，不要分段孤立地看两段代码。
失败检查里只记录日志 / 弹提示、却没有 return / 抛出 / 中止后续流程的，
同样视为「未中止」。

## 反例
```cpp
if (!m_passwordManager.initialize())
{
    QMessageBox::critical(this, "错误", "无法初始化加密数据库。");
    // 只弹了提示，没有 return / throw
}
refreshTable();  // 失败后仍继续使用未初始化的 m_passwordManager
```
上面这段要报「初始化失败后未中止操作」——弹窗不等于中止。
