# §7 明确禁止项 — 禁止未验证输入 / 敏感信息泄露 — 密码不应输出到日志

## 关联规则
- §7 明确禁止项 — 禁止未验证输入 / 敏感信息泄露 — 密码不应输出到日志

## 代码特征
- 代码中存在直接对敏感字段（如 `.password`、`.secret`、`.key`、`.token` 等）调用 `qDebug()`、`qInfo()`、`qWarning()` 或 `std::cout` 等日志/调试输出语句。
- 典型模式：`qDebug() << 变量名 << 变量名.password << ...;` 或类似链式输出，其中包含以 `password`、`passwd`、`secret`、`key`、`token` 命名的成员变量或函数返回值。
- 危险输出可能出现在循环、事件处理、请求处理等可执行路径中，不限于单一语句。

## 修复步骤
1. **定位违规行**：查找所有包含 `qDebug() <<` 或其他日志宏且右侧包含 `password`、`secret`、`key`、`token` 等敏感字段的代码行。
2. **移除敏感信息输出**：将该日志行中直接输出敏感字段的部分删除或替换为无害占位符（例如 `"(password hidden)"`），确保敏感数据不被写入日志流。
   - 替换示例：  
     `qDebug() << e.siteName << e.username << e.password;`  
     改为  
     `qDebug() << e.siteName << "(password hidden)";`
   - 或完全移除该日志行（仅保留必要的非敏感信息日志）。
3. **添加安全提醒注释**（可选但推荐）：在文件头部（如 `#include` 附近）或修复后的日志行上方添加注释，提醒开发者禁止输出敏感信息，例如：  
   `// 安全提醒：禁止将密码明文输出到日志/调试输出，防止敏感信息泄露`
4. **检查所有日志输出点**：确认整个文件中所有可能输出密码、密钥等敏感数据的地方均已清理，避免遗漏。
