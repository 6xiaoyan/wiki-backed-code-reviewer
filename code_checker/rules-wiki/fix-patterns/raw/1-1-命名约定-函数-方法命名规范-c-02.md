# §1.1 命名约定 — 函数/方法命名规范 [C-02]

## 关联规则
- §1.1 命名约定 — 函数/方法命名规范 [C-02]：获取数据的 getter 函数必须以 `get` 或 `fetch` 等动词前缀开头，禁止以名词直接作为函数名。

## 代码特征

以下代码模式会触发此违规，fix_agent 可按此模式识别同类问题：

1. **无动词前缀的 getter 声明**：在头文件中存在形如 `std::string username() const;` 的成员函数声明。该类函数的特点：
   - 返回类型为成员变量类型（`std::string`、`int`、`bool`、`QString` 等）
   - 函数名以名词开头（如 `username`、`password`、`siteName`）
   - 带有 `const` 修饰符（通常表示只读 getter）
   - 函数体仅为 `return 成员变量;`

2. **同名的 cpp 定义**：在源文件（`.cpp`）中存在对应的函数定义，如 `std::string PasswordDialog::username() const { return m_username; }`。

3. **跨文件调用点**：其他源文件（如 `mainwindow.cpp`）中通过对象调用该 getter，例如 `dlg.username()`。

典型特征总结：**关键词匹配** — 搜索 `std::string \w+\(\) const` 或 `QString \w+\(\) const` 且函数名首词为名词、非 `get`/`fetch`/`is`/`has` 等动词前缀时，即命中此模式。

## 修复步骤

按以下顺序执行修改，确保跨文件同步完整，避免编译失败：

1. **重命名头文件中的声明**
   - 打开 `passworddialog.h`
   - 定位 `    std::string username() const;`
   - 改为 `    std::string getUsername() const;`
   - 说明：将函数名首词替换为 `get`，并将原名词首字母大写（如 `username` → `getUsername`）

2. **重命名 cpp 文件中的函数定义**
   - 打开 `passworddialog.cpp`
   - 定位 `std::string PasswordDialog::username() const`
   - 改为 `std::string PasswordDialog::getUsername() const`
   - 说明：头文件与 cpp 定义必须同步修改，否则产生链接错误

3. **查找并更新所有调用点**
   - 在项目全局搜索 `dlg.username()` 或 `username()`（限定在业务代码调用上下文中）
   - 逐个替换为 `dlg.getUsername()`
   - **注意**：若同时存在 `setUsername` 等 setter，不要误替换；只替换 getter 调用的 `dlg.username()` 形式

4. **消除同名片段歧义（如适用）**
   - 若 `mainwindow.cpp` 中存在多处相同的调用片段（如 `dlg.siteName(), dlg.username(),` 出现两次），必须结合上下文区分：
     - 搜索附近的调用函数名：`addEntry` 或 `updateEntry`
     - 将 `addEntry` 代码块中的 `dlg.username(),` 替换为 `dlg.getUsername(),`
     - 将 `updateEntry` 代码块中的 `dlg.username(),` 替换为 `dlg.getUsername(),`
   - 使用足够多的上下文行（如上一行 `dlg.siteName(),`、下一行的括号结构）作为替换匹配文本，避免误替换

5. **验证修改完整性**
   - 再次全局搜索 `\busername\b`，确认除成员变量 `m_username`、`setUsername` 参数、`PasswordEntry` 结构体成员 `e.username` 外，不存在独立的 `username()` getter 调用
   - 确认所有 `dlg.username()` 均已改为 `dlg.getUsername()`
   - 编译工程，确保无未解析的外部符号或调用不匹配错误
