# 下一步：为什么规则对模型的帮助不同

本轮观察到Qwen无规则F1为66.25%，略高于GLM的65.00%和MiniMax的58.59%；MiniMax有规则F1为68.30%，略高于Qwen的66.73%。这支持研究模型如何使用规则，但差距不足以证明固定的模型能力排名。下面是后续方案，尚未执行。

## 已有结果说明什么

MiniMax加入规则后覆盖37→46个漏洞，同时参考精确率76.60%→81.13%，报告数47→53。Qwen覆盖43→48个漏洞，但精确率82.98%→72.88%，报告数47→59；它扩展了检查范围，也带来更多没有被确认的报告。GLM覆盖43→35个，原报告存在跨位置问题合并，可能受到按主行号找答案的影响。

因此不能只问“谁更聪明”，需要具体找出：规则提示了哪些新增检查；有没有把普通代码过度当成违规；已有正确发现为何消失；模型是否把多个修复事项合并而丢掉清楚的定位。

## 系统可以改哪几个地方

1. **让模型拿到需要的规则和代码。** 当前B组只是规则目录可见，不代表模型真正读完。既有轨迹中MiniMax读了多份全文，Qwen主要读标题。后续应比较“模型自己找材料”和“给定同一份相关材料”，判断差异来自搜索还是理解。
2. **按实际代码位置组织任务。** 把一个函数或一条跨文件调用关系，以及相关条款一起交给模型，观察是否能补足授权、会话和前端数据流。不能把标准答案位置告诉审查模型。
3. **控制报告扩张。** Qwen规则组新增报告较多但确认比例下降。可以让模型解释规则为什么适用于当前代码，例如普通票号与认证令牌是否确实承担相同的安全作用；不要只因规则提到random就一律报安全漏洞。
4. **保持独立问题的位置清楚。** GLM把多个位置合并到一个报告，既不便开发者修复，也影响当前按位置生成答案候选。可以在统一提示词中要求独立修复事项分别报告，不按标准答案定向拆分。

## 下一轮怎么比较

先对当前条件重复运行，观察Qwen无规则与MiniMax有规则的优势是否持续。之后一次只改变一种安排：给相同规则材料、给完整调用关系、或改变任务拆分。模型、代码、规则版本、基本提示词和判分标准保持可比，同时记录实际读到的材料、token和费用。

主分数仍使用已经确认的三项检查和语义判断，CWE单列。若要改变位置窗口、增加调用点匹配或加入其他检查，应先说明如何改变结果，并取得用户批准。当前报告不因为选定主力模型就临时改变分数。

如果固定相关材料后MiniMax仍更好，说明更值得研究规则理解和应用；如果差距消失，改进重点应放在材料查找和任务组织。最终系统目标是让不同模型都能稳定找到适用条款和相关代码，而不是依赖某个模型恰好擅长自主搜索。
